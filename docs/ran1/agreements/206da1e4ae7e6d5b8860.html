R1-2609262 FL Summary #6: GNSS resilient NR-NTN operation Moderator (Thales)

Agreement:

For TA control in RRC_CONNECTED for GNSS-resilient NR-NTN operation:

  • Explicitly define the mathematical formula for TA drift compensation in TS 38.211 / TS 38.213 using the form:

    • NTA=NTA(old)+TAdrift×(t−t0)/Tc

    • NTA is TA applied at t

    • NTA(old) is NTA at t0

  • The TA drift rate (TAdrift) is derived from the accumulated closed-loop frequency adjustment (FA).

  • The reference time (t0​) is defined as the uplink application time of the most recently received closed-loop FAC or TAC.

  • The derivation of TAdrift from the accumulated FAC is explicitly defined in the spec

    • TAdrift=FAfUL , fUL is the uplink carrier frequency (i.e. FrequencyInfoUL )

    • FA is the accumulative FAC, this will be discussed in a separate proposal.

NOTE: It is up to the spec editor how the capture the above in the specs.

Agreement:

Support the following explicit baseline equation for the Closed-Loop FA value update:

FAnew=FAold+FACMAC−CE

Where the MAC CE parameters are defined as follows:

  • FAnew is accumulative FA

  • FACMAC−CE is the value of the FAC in MAC CE

The PRACH transmission applies a Closed-Loop FA value of zero.

For initial access in GNSS resilient operation, when the FAC is indicated in the Msg2 RAR (FACRAR), the FA is

FAnew=FACRAR.

The application time follows the same procedures as for TAC.

Agreement:

The value of the scaling factor in the agreement of TA offset granularity is set to be equal to 64.

Agreement:

For determining the temporal relationship between the two ROs of one RO-pair when PRACH repetition is not used,

Consecutive ROs: The two ROs are two consecutive valid ROs in the time domain, based on the PRACH configuration index/a SSB.

  • The definition of a "Valid RO" follows existing specifications.

  • Additional RO Validity Rule: ROs in a window configured by the NW are valid

    • UE drops all ROs within a RO window of size X (e.g. X=16) except Y (e.g.Y=2,4,6,8) consecutive ROs starting from an Offset (P, Q) where P (0≤P≤X) is radio frame index and Q (0≤Q<10) is subframe index, if configured by network.

    • Network configures X, Y, P, Q.

    • The problem related to beam-hopping that can be solved by this solution, is also applied to Rel-20 GNSS-based/GNSS-resiliance UEs using single PRACH

Agreement:

The determination of whether a last known GNSS location is "sufficiently valid" is left up to UE implementation provided RAN4 timing/frequency requirements are satisfied from RAN1 perspective.

  • Assistance information (i.e. maximum uncertainty radius) may be provided by the network for the UE to decide whether its last known GNSS location is "sufficiently valid” or not.

NOTE 2: The fundamental purpose of the validity check is to ensure the uplink time and frequency offset observed by the network are within the tolerances of the network-configured PRACH format(s), bounded by the maximum acceptable differential delay and Doppler shift.
