Observation

Initial observations on Preamble sequence evaluations. The following observations may be further updated based on additional inputs from companies in future meetings. Whether/how to capture the following observation(s) to TR is separately discussed

Missed detection / false detection for candidate preamble sequences

10 sources (Xiaomi, Fraunhofer, vivo, CATT/CICTCI, Huawei/HiSilicon, Apple, Ericsson, Qualcomm, MediaTek, ZTE/Sanechips) [Source #12, Source #13, Source #6, Source #14, Source #1, Source #4, Source #17, Source #8, Source #3, Source #16] reported that, under low UE speed and single-user conditions, the missed detection performance of the candidate preamble sequences is comparable to that of the NR ZC baseline, whereas the false detection performance differs noticeably among the candidates. The difference depends on the cross-correlation properties of the sequence pool, the detection threshold setting and receiver algorithm, the false-alarm calibration, and the number of preambles per RO. NR ZC (and the ZC-equivalent EZC#2) generally shows the lowest false detection rate among the evaluated candidates. In addition, with achieving reduced false detection rate, miss detection probability performance is impacted.

With single-user and/or low UE speed conditions,

  • 9 sources report that all candidate sequences (e.g., EZC, Gold/GoldxM, m-sequence based, QPSK modulated M, CGS/e-CGS, Gabor-frame based) achieve 1% missed detection within ~0.2 dB~1.3 dB of each other, and within ~0.9 dB of NR ZC when evaluated at equal capacity, equal energy and a common false-alarm operating point (Xiaomi, Fraunhofer, vivo, CATT/CICTCI, Huawei/HiSilicon, Apple, Ericsson, Qualcomm, MediaTek) [Source #12, Source #13, Source #6, Source #14, Source #1, Source #4, Source #17, Source #8, Source #3];

  • One source reported that EZC#2 has the same detection performance as NR ZC (MediaTek) [Source #3].

  • One source reported that the detection performance of EZC#1 is not as good as that of NR ZC. (ZTE/Sanechips) [Source #16];

  • 5 sources report that most non-ZC candidates have higher Type-1 false detection than NR ZC (Xiaomi, vivo, CATT/CICTCI, Ericsson, Qualcomm) [Source #12, Source #6, Source #14, Source #17, Source #8], e.g., ~3%~7% compared to below 1% for NR ZC with 64 preambles/1 user per RO at the 1% MDR target SNR of -11 dB (Qualcomm) [Source #8], and ~53% per occasion with 1 UE per RO for a truncated m-sequence pool (CATT/CICTCI) [Source #14]; the higher false detection is attributed to the worse cross-correlation properties of the new sequences. 2 sources reported that EZC#2 shows ZC-equivalent false detection (vivo, Ericsson) [Source #6, Source #17]. One source reported that, with the same detection statistic and false-alarm calibration, all candidates including Gold/GoldxM with FD-CS achieve a false detection rate below 0.1% per RO (Apple) [Source #4];

  • One source reported that, with a restricted false detection algorithm (detection threshold set for a 1% false detection rate) and 64 preambles/1 user per RO, miss detection probability performance is impacted, all new sequences get worse miss detection performance than baseline ZC (ordered ZC > vivo CGS > MTK Z4 > Apple GoldxM > HW EZC/Apple Gold > LG), with 0.5 dB to 5 dB miss detection degradation (Qualcomm) [Source #8].

  • One source reports that gradient optimized low PAPR sequence can achieve ~2.8 dB PAPR gain (at the 50th percentile of per-sequence maximum PAPR) compared with ZC sequence, and more compared with other new sequences. Meanwhile, gradient optimized low PAPR waveform for PRACH sequence can achieve at least 8 times capacity than baseline ZC sequence, if needed. For 64 and 128 preambles per RO, miss detection probability is similar among the proposed new sequences, e.g., EZC and Gold sequence, other than the LG sequence which is worse (Qualcomm) [Source #8]

  • One source reports that the false detection rate can be reduced with an advanced threshold setting (e.g., based on both thermal noise and interference estimation), however, miss detection probability performance is impacted, NRZC and e-CGS with 0.1 to 0.8 dB miss detection degradation, and other new sequences with 0.5 to 1.3 dB miss detection degradation (vivo) [Source #6];

With more users,

  • One source reports that the detection performance of EZC#1 is not as good as that of NR ZC. With 8 users per RO, the SNR corresponding to 1% MDR of EZC#1 is 0.5 dB higher than ZC. The SNR corresponding to 0.1% FDR of EZC#1 is 0.7 dB lower than ZC. For MDR, the MDR performance of EZC#1 relative to ZC degrades as the number of UEs increases (ZTE/Sanechips) [Source #16];

  • One source reported that, with 8 UEs per RO under equal-power load, Type-1 false detection per occasion spans 0.01% to 99% across the candidate families, e.g., ~0.01% for EZC with a single-lambda pool at 64 preambles per RO and saturating at ~99% for a truncated m-sequence pool, and that NR ZC is the only family that holds both the calibrated Type-1 false detection floor and the 1% loaded missed detection target (CATT/CICTCI) [Source #14];

  • One source reported that, with the restricted false detection algorithm, missed detection is further degraded with 128 preambles/2 users per RO (with the truncated m-sequence hitting an error floor), and all sequences including NR ZC hit an error floor and cannot achieve 1% MDR with 512 preambles/8 users per RO (Qualcomm) [Source #8];

High mobility, Doppler, or frequency-offset robustness for candidate preamble sequences

14 sources (Xiaomi, LG Electronics, Samsung, Qualcomm, Ericsson, Fraunhofer, vivo, Huawei/HiSilicon, Apple, MediaTek, CATT/CICTCI, ZTE/Sanechips, Lenovo, Nokia) [Source #12, Source #20, Source #2, Source #8, Source #17, Source #13, Source #6, Source #1, Source #4, Source #3, Source #14, Source #16, Source #5, Source #18] reported that, at low UE speed, all candidate sequences have similar missed detection performance, while at high UE speed (e.g., 500 km/h and above) or large frequency offset, the performance depends on whether the sequence has time-frequency ambiguity, whether restricted sets are used, which preamble format is used, and the receiver assumptions (e.g., number of frequency hypotheses, advanced receiver, repetition). Sources differ on whether NR ZC with restricted sets is sufficient for the high-speed TN scenarios.

With high UE speed and/or large frequency offset,

  • 5 sources report that NR ZC with restricted sets (Type A/B) or with short preamble format (30kHz SCS), , achieves missed detection comparable to or slightly better than the other candidates at 120 km/h~500 km/h, and one of these sources reported robust detection for UE speeds up to 1000 km/h at 3.5 GHz and 7 GHz (Xiaomi, LG Electronics, Samsung, Qualcomm, Ericsson) [Source #12, Source #20, Source #2, Source #8, Source #17];

  • One source reports that TN high mobility/doppler scenarios can configure short format e.g. B4 and C2 with e.g. SCS 30 KHz without facing any doppler issue (Qualcomm) [Source #8].

  • 4 sources report that NR ZC and ZC-equivalent sequences (e.g., EZC#2) cannot reach 1% missed detection at 500 km/h and above (e.g., MDP floor of ~0.1 for format 0 at 500 km/h), whereas sequences without time-frequency ambiguity (e.g., EZC-HW, Gabor-frame based, CGS, Gold-based, m-sequence based) reach 1% missed detection at ~-12 dB SNR or lower at 500 km/h (Fraunhofer, vivo, Huawei/HiSilicon, Apple) [Source #13, Source #6, Source #1, Source #4]. One of these sources report that non-ZC and hierarchical ZC + non-ZC sequences show consistent missed detection performance for UE speeds from 3 km/h to 500 km/h, and that the hierarchical ZC + non-ZC design keeps the receiver complexity low over the whole FO range, whereas the number of integer FO hypotheses required by a non-ZC sequence alone grows with the FO range to be covered (Apple) [Source #4]. Two of these sources report that EZC-HW and Gabor-frame based sequences also reach 1% missed detection at UE speeds up to 1000 km/h with a loss of at most ~2 dB relative to 3 km/h (Fraunhofer, Huawei/HiSilicon) [Source #13, Source #1];

  • One source report that NR ZC with restricted set B outperforms the QPSK-modulated m-sequence by ~1.1 dB in the HST scenario at 7 GHz, but with a much higher false detection rate (MediaTek) [Source #3]. One source reported that removing restricted sets requires a multi-hypothesis frequency search of ~9~13 hypotheses at 500 km/h, and a dual-sequence format (length 139, 30 kHz) reaches 1% missed detection at ~-6 dB at 500 km/h without a restricted set (CATT/CICTCI) [Source #14];

  • 2 sources report that multi-root ZC constructions improve frequency-offset robustness, e.g., reaching 1% missed detection ~4~5 dB earlier than single-root constructions at 1.0 ppm (ZTE/Sanechips, Lenovo) [Source #16, Source #5]. Two sources reported that bi-root ZC over two occasions performs 1.2 dB~1.9 dB worse than the other options (NR ZC, non-ZC, and hierarchical ZC + non-ZC) at 3 km/h and does not work at 60 km/h and above, and that multi-root ZC becomes vulnerable in NLOS channels with large Doppler spread (Apple, Huawei/HiSilicon) [Source #4, Source #1];

  • One source reports that two roots ZC sequence can be used for high-speed train scenario when needed, where UL channel model for HST is agreed as single tap strong LoS channel model, with similar two roots performance as NTN TDL-C channel model (Qualcomm) [Source #8].

  • One source reports that two-seq ZC format can handle large frequency offsets, e.g., at 5 ppm@7GHz, to satisfy the 1% MDR requirement, 6G#Format 1 and 6G#Format 2 achieve an SNR of approximately -8 dB and -11dB, respectively (vivo) [Source #6];

  • One source report that, in an HST scenario at 3.5 GHz with 1740 Hz Doppler shift, Gold and cubic ZC with receiver frequency hypotheses outperform NR ZC in format 0 by a large margin but perform the same as NR ZC without hypotheses, while with the tone-assisted format 0A, unrestricted NR ZC, Gold and cubic ZC without hypotheses perform the same and better than format 0 with hypotheses; Type-1 false detection stays below 1% in all cases except unrestricted NR ZC in format 0 (Nokia) [Source #18];

  • One source reported that for 2-root ZC construction with overlapped sequences is more robust than that with TDM sequences under the condition of LOS with a smaller K value and the Doppler spread is corresponding to 60 km/hr (MediaTek) [Source #3].

Correlation, PAPR/CM and sequence pool size of candidate preamble sequences

  • 4 sources report that NR ZC has the best periodic auto-correlation (zero sidelobes at non-zero delays), with EZC#2 comparable to NR ZC, while the other candidates show non-zero sidelobes (e.g., ~0.0345 for eZC), and π/2-BPSK Gold/m-Gold show the worst maximum auto-correlation and a larger auto-correlation variance; higher auto-correlation sidelobes lead to higher cross-correlation between cyclic shifts of the same root (Xiaomi, vivo, Ericsson, Qualcomm) [Source #12, Source #6, Source #17, Source #8]. Sources differ on e-CGS, reported as comparable to NR ZC (vivo) [Source #6] or much worse than NR ZC (Qualcomm) [Source #8];

  • 6 sources report that NR ZC (and the ZC-equivalent EZC#2) has the lowest inter-sequence cross-correlation, e.g., all NR ZC cross-correlations below 0.18, while the other candidates (e.g., truncated m-sequence, π/2-BPSK Gold/m-sequence-scrambled Gold, CGS/e-CGS, QPSK-modulated m-sequence) show higher maximum cross-correlation, with the truncated m-sequence showing the widest distribution and a tail beyond 0.25 (Xiaomi, ZTE/Sanechips, vivo, Ericsson, Qualcomm, Huawei/HiSilicon) [Source #12, Source #16, Source #6, Source #17, Source #8, Source #1]. One of these sources reported that the ZC-based group (NR ZC, EZC-MTK, EZC-HW) shows superior correlation properties among all candidates, and that frequency-domain cyclic shifts of QPSK-modulated m-sequences give a higher cross-correlation (2√N + 1) than ZC (Huawei/HiSilicon) [Source #1]. One of these sources reported that Z4 roots without frequency shifts, EZC#1 frequency shifts for a fixed root, and EZC#2 roots are similar to ZC over the 70th~93rd percentile range, whereas Z4 frequency shifts for a fixed root, EZC#1 roots and Gold/m-Gold are much worse (Ericsson) [Source #17];

  • One source report that for EZC#1, Z4, Gold, and m-Gold ambiguity functions, there are no clear peaks besides the main peak, but the general (correlation metric) background level is significantly higher than for ZC (Ericsson) [Source #17];

  • 4 sources report that some candidates achieve cross-correlation close to NR ZC: all evaluated candidates show similar cross-correlation distributions, with a 90th-percentile cross-correlation of 0.11~0.14, whereas the maximum cross-correlation differs more widely (0.18~0.43), and FD-CS gives lower maximum cross-correlation than π/2-BPSK for Gold and GoldxM (Apple) [Source #4]; e-CGS deviates from NR ZC by only 0.02~0.04 ("pair all") and ~0.08~0.14 ("pair max") at the 0.9 CDF level (vivo) [Source #6]; Gabor-frame based GFA is comparable to NR ZC and EZC-MTK for L = 139 (0.171 at the 0.9 CDF level) and ~12.4% higher than NR ZC for L = 839, while GFB is ~21% and ~54% higher (Fraunhofer) [Source #13]; and CGS has comparable or better cross-correlation than NR ZC, whose cross-correlation sidelobes can reach -15 dB with ~40% above the theoretical -21.5 dB, and multi-channel CGS with K = 4 reduces cross-correlation by ~6 dB (Samsung) [Source #2];

  • 3 sources report that NR ZC provides among the lowest PAPR of the evaluated sequences, e.g., the lowest median PAPR (with the truncated m-sequence slightly better only at high percentiles), the lowest maximum PAPR, or, together with EZC#2, the best 90th-percentile PAPR ahead of EZC#1, the QPSK-modulated m-sequence and overlapped 2-root ZC (Xiaomi, ZTE/Sanechips, MediaTek) [Source #12, Source #16, Source #3]. 5 sources report that ZC-based/ZC-like candidates have PAPR similar to or worse than NR ZC, e.g., EZC#2 identical to NR ZC, EZC#1/Z4 and the QPSK-modulated m-sequence slightly worse, and NR ZC, EZC-MTK, EZC-HW and GFA comparable over the universal sequence set (vivo, Qualcomm, MediaTek, Fraunhofer, Huawei/HiSilicon) [Source #6, Source #8, Source #3, Source #13, Source #1]. 2 sources report that subset selection from the sequence pool can lower PAPR, e.g., EZC-HW and GFA ~1.9 dB lower than NR ZC for L = 139 (while NR ZC remains lowest for L = 839), and EZC-HW comparable to π/2-BPSK sequences for pools of 128 or 512 preambles per RO (Fraunhofer, Huawei/HiSilicon) [Source #13, Source #1];

  • 5 sources report PAPR/CM gains for some new sequences, e.g., e-CGS/CGS with ~3 dB (CCDF 10^-2) to ~4 dB (CCDF 10^-3) lower PAPR than NR ZC and much smaller PAPR variance, or the lowest maximum PAPR/CM (1.67 dB/-0.23 dB); π/2-BPSK Gold and GoldxM with ~1 dB lower PAPR than NR ZC, ~1 dB lower PAPR/CM than the other new sequences, or a maximum PAPR of 5.88 dB~6.58 dB and maximum CM of 0.59 dB~0.81 dB compared with 6.56 dB and 2.38 dB for NR ZC; and the truncated m-sequence and Gold×M improving both PAPR and CM (vivo, Apple, Ericsson, Qualcomm, CATT/CICTCI) [Source #6, Source #4, Source #17, Source #8, Source #14]. One source reported that a gradient-optimized low-PAPR waveform achieves ~2.8 dB PAPR gain over NR ZC at the 50th percentile of the per-sequence maximum PAPR (Qualcomm) [Source #8];

  • 3 sources report CM and PAPR trade-offs: NR ZC has a much larger CM spread than the other sequence types, with about half of the ZC sequences having better CM than most other types (Ericsson) [Source #17]; the QPSK-modulated m-sequence has a smaller CM standard deviation than ZC, removing the need to order roots by CM, and overlapped 2-root ZC with an optimized relative cyclic shift has lower CM than with a random shift. Regarding the PAPR at 90%, NR ZC and EZC#2 is reported to outperform EZC#1, which in turn outperforms the QPSK-modulated M-sequence and overlapped 2-root ZC with relative cyclic shift of -1, and then outperforms than overlapped 2-root ZC with relative cyclic shift of random (MediaTek) [Source #3]; and EZC and Z4 trade PAPR against CM rather than improving both, while zero-padded Gold costs +4.2 dB PAPR and +3.5 dB CM at the 90th percentile normalized to an LRA = 839 pool (+5.1 dB/+4.6 dB at M = 1024) (CATT/CICTCI) [Source #14]. One source reported that PAPR/CM comparisons are only meaningful at a common measurement point, i.e., an oversampled waveform, the useful symbol and a ZC reference of the same length (CATT/CICTCI) [Source #14];

  • 5 sources report on the sequence pool size of the candidates: the number of base sequences is (LRA + 2) × LRA for the m-sequence scrambled Gold sequence and LRA + 2 for the Gold sequence, compared with LRA − 1 root sequences for NR ZC (Apple) [Source #4]; Utilizing a new sequence for the preamble in 6GR, e.g., QPSK modulated M sequence, is reported to avoid the NR ZC restricted set constraints and achieve a capacity that is N (the sequence length) times that of NR's for the same sequence length, and the QPSK-modulated m-sequence provides over 2500 times the sequence capacity of NR ZC under the HST scenario at 7 GHz (MediaTek) [Source #3]; the number of CGS sequences is decoupled from the sequence length, e.g., e-CGS with 1024 sequences (vivo) [Source #6]; the large-pool families (ZC, EZC, Gold×M) range from 5×10^4 to 10^9 codes (CATT/CICTCI) [Source #14]; and ZC with frequency-domain OCC doubles the number of available preambles with a marginal increase in average cross-correlation (Lenovo) [Source #5]. One source reported that non-ZC families are restricted to lengths of 2^k − 1, so truncation or padding degrades the correlation properties, and that the low-PAPR Gold sequence has limited capacity while capacity-enhancing approaches (m-scrambling or frequency-domain cyclic shifts) degrade correlation or increase PAPR (Huawei/HiSilicon) [Source #1];

Detection performance with different preamble-pool sizes or multiple users

7 sources (vivo, CATT/CICTCI, MediaTek, Apple, Qualcomm, Huawei/HiSilicon, Nokia) [Source #6, Source #14, Source #3, Source #4, Source #8, Source #1, Source #18] reported that the detection performance degrades as the number of preambles per RO and/or the number of UEs per RO increases, primarily through increased Type-1 false detection and a missed detection error floor under load rather than through single-user missed detection. The degradation depends on how the preamble capacity is extended (additional roots/cyclic shifts, new sequences, or coding across sequence segments), the cross-correlation properties of the pool, the preamble collision rate, and the receiver algorithm.

With increased preamble-pool sizes or multiple users per RO,

  • 4 sources report that the single-user missed detection loss from increasing the number of preambles per RO is small, i.e., ~0.5 dB from 64 to 128/256 preambles and ~0.8 dB from 64 to 512 preambles, ~0.12 dB from 64 to 128 and ~0.22 dB from 64 to 256 preambles with the detection threshold calibrated to a per-RO false-alarm budget, or nearly identical performance for 64 preambles/1 user and 128 preambles/2 users per RO (vivo, CATT/CICTCI, MediaTek, Apple) [Source #6, Source #14, Source #3, Source #4];

  • 2 sources report that Type-1 false detection increases significantly with the number of preambles per RO for all sequences (vivo, Qualcomm) [Source #6, Source #8]. One source reported that Type-1 false detection is 8% for NR ZC compared to ~20%~40% for other candidates with 128 preambles/2 users per RO at the 1% MDR target SNR of -11 dB, and dramatically worse (close to or beyond 100% for the new sequences, and very high for NR ZC) with 512 preambles/8 users per RO (Qualcomm) [Source #8]; One source report that, with the detection threshold calibrated to a false-alarm defined per RO (Option 2), the false detection rate stays below the 0.1% budget and grows only mildly with the number of preambles per RO, i.e., 0.036%, 0.040% and 0.045% per RO at 64, 128 and 256 preambles per RO (Apple) [Source #4];

  • 3 sources report that the missed detection under load exhibits an error floor, without achieving 1% miss detection rate, e.g., ~1.2% for 512 preambles with 8 UEs per RO and ~1.1%~5.6% for the candidate families with 8 UEs per RO, while 128 preambles reach 1% from -4 dB (CATT/CICTCI, Qualcomm, Huawei/HiSilicon) [Source #14, Source #8, Source #1]. One of these sources reported that sequences without capacity enhancement (NR ZC, multi-root ZC, EZC-MTK, Gold) suffer from an error floor due to preamble collisions, while sequences with capacity enhancement maintain good missed detection performance (Huawei/HiSilicon) [Source #1]. One source reported that missed detection with NR ZC still passes 1% at the required SNR as the number of users increases (Samsung) [Source #2];

  • One source report that a dual-sequence preamble with a codeword check between the two segments provides 512 identities per RO with missed detection coinciding with the 64-preamble reference, and Type-1 false detection of 0.015~0.10 times that of the reference pools (CATT/CICTCI) [Source #14];

  • One source report that, with 4 unique UEs per RO at low Doppler (12 km cell, 3.5 GHz), placing the preambles on cyclic shifts of the same root or on distinct roots gives a marginal difference, with 1% missed detection at ~-5.0 dB~-5.1 dB in format 0 and ~-7.8 dB~-8.1 dB with the tone-assisted format 0A; Type-1 false detection of unrestricted Gold in format 0 reaches 3.0%~3.9% at 0 dB, whereas unrestricted NR ZC stays near 0.05% (Nokia) [Source #18];

Transmit and receive complexity:

  • Two sources reports the implementation complexity for non-ZC new sequences that non-ZC based sequence do not have such good property as ZC that DFT of ZC sequence is another ZC sequence. Hence, DFT implementation step is needed for those non-ZC proposed sequences generation for UE implementation with prime numbers (139, 839, ...) or 2^n – 1 (127, 255, …) which are all not standard 2^x * 3^y * 5^z DFT length format, then DFT hardware implementation will introduce additional cost, timeline and complexity (Qualcomm, Ericsson) [Source #8, Source #17].

  • One source reports that gradient optimized low PAPR waveform, with standard DFT length of {144, 864} can solve the DFT implementation complexity with the close length as NR of {139, 839} (Qualcomm) [Source #8].

  • One source reports that CGS-based PRACH sequences have low hardware implementation complexity without requiring DFT (vivo) [Source #6];

  • 2 sources report that, for non-ZC sequences, frequency-offset robustness without restricted sets is obtained at the cost of a multi-hypothesis frequency search at the receiver, e.g., ~9~13 frequency hypotheses at 500 km/h and a per-occasion search space of 64 to 2.2×10^6 hypotheses for the candidate receivers compared with 64 for the NR ZC reference (CATT/CICTCI) [Source #14], and detection complexity that scales linearly with the integer CFO range normalized by the PRACH SCS, i.e., ~9 times (S band) and ~65 times (Ku band) the detection complexity of 2-root ZC in NTN (Qualcomm) [Source #8]. One of these sources reported that missed detection results presented without such complexity accounting are not comparable with a single-hypothesis ZC baseline (CATT/CICTCI) [Source #14];

  • One source reports that the detection complexity of the QPSK-modulated m-sequence is the same as that of NR ZC in TN low-speed scenarios, ~75% of NR ZC in TN HST scenarios, and ~190% of NR ZC in NTN GNSS-resilient scenarios assuming 50 kHz CFO (MediaTek) [Source #3];

  • One source reports that the EZC sequence provides low detection complexity together with large capacity and handling of large frequency offset (Huawei/HiSilicon) [Source #1];

  • 3 sources report complexity drawbacks of non-ZC sequences, e.g., additional receiver complexity, processing and storage (Panasonic) [Source #23], and increased receiver complexity for π/2-BPSK-modulated Gold codes and standardization complexity for CGS (Sony), whereas the performance, complexity and maturity of ZC have been verified in network and UE products for decades (OPPO) [Source #15];

  • 5 sources propose that complexity be considered or reported together with detection performance when evaluating candidate sequences, e.g., receiver complexity for Gabor-frame based sequences (ZTE/Sanechips) [Source #16], UE/network complexity, processing and storage for non-ZC and enhanced ZC sequences (Panasonic) [Source #23], receiver complexity when comparing phaseMode {off, cubic} (TCL) [Source #19], detection complexity of root variation combined with cover-code spreading across repetitions (Lenovo) [Source #5], and an energy-weighted metric (e.g., SQNR at the correlation peak) for implementation complexity comparisons across sequence families (CATT/CICTCI) [Source #14];

  • One source proposes to study detection enhancements for high Doppler scenarios without modifying the existing base station receiver algorithm and complexity (Nokia) [Source #18];

New/reduced preamble formats: detection and coverage trade-offs

9 sources (OPPO, NTT DOCOMO, Ericsson, vivo, IIT, Lenovo, MediaTek, CATT/CICTCI, Nokia) [Source #15, Source #7, Source #17, Source #6, Source #11, Source #5, Source #3, Source #14, Source #18] reported that new or modified PRACH formats can provide coverage, capacity, or Doppler-robustness benefits depending on the PRACH SCS, sequence length, number of repetitions, and occupied bandwidth, with a trade-off between Doppler robustness (larger SCS) and coverage/capacity (longer sequence and duration). The relative ranking of the new short formats differs among sources depending on the carrier frequency, UE speed, and restricted-set assumptions.

With new/reduced preamble formats,

  • One source report that format B4 achieves ~5 dB better performance than format 3 at 7.125 GHz and 500 km/h, and an enhanced format 3 with 7.5 kHz SCS achieves 1% MDR at -10 dB, close to format B4 (OPPO) [Source #15];

  • 2 sources report that, among the new short formats, F4-1 (5 kHz SCS, L=839, Rep=2) and F4-3 (7.5 kHz SCS, L=839, Rep=3) outperform F4-2 (2.5 kHz SCS, L=839, Rep=1) by ~2 dB and ~3 dB at low UE speed, with F4-3 best at high UE speed (NTT DOCOMO) [Source #7], whereas at 120 km/h F4-1 (2.5 kHz SCS, L=839, Rep=1), F4-2 (5 kHz SCS, L=839, Rep=2) and NR format B4 have similar coverage, i.e., link budget, and F4-1 (2.5 kHz SCS, L=839, Rep=1) degrades more at 500 km/h than F4-2 (5 kHz SCS, L=839, Rep=2) and F4-3 (5 kHz SCS, L=839, Rep=1) (Ericsson) [Source #17];

  • 3 sources report that long-sequence formats (e.g., format 2) can meet or significantly reduce the gap to the extended coverage target of 153 dB MaxCL, e.g., ~3 dB lower SNR than format 1 with 5 ppm FO at 7 GHz, and a remaining coverage gap of 7.91 dB at 1% MDR (vivo, NTT DOCOMO, IIT) [Source #6, Source #7, Source #11];

  • 3 sources report coverage/capacity gains from modified formats, e.g., ~2 dB coverage gain with frequency-domain OCC at double the bandwidth, ~75% resource overhead reduction with reduced-bandwidth PRACH, and a dual-sequence long format carrying 512 identities within 0.2 dB~1.0 dB of a two-repetition 64-preamble design (Lenovo, MediaTek, CATT/CICTCI) [Source #5, Source #3, Source #14];

  • One source report that the tone-assisted format 0A maintains the same PAPR as format 0 for all sequence families, with a consistently lower cubic metric (Nokia) [Source #18];

  • One source shows that, among the new long format with shorter duration, e.g., format 3-1 and format 3-2 provide comparable coverage performance while achieving a 6 to 12 times increase in capacity compared with NR format B4, and format 3-3 provide better coverage performance while achieving a 6 time increase in capacity compared with NR format B4 (vivo) [Source #6];

Overlapping PRACH formats

2 sources reported that overlapping different PRACH formats in the same or partially overlapping ROs can improve PRACH resource utilization and increase random-access opportunities. Cross-format interference/false detection can occur when a correlation peak of one format falls within the detection window of another format, but it can be mitigated by different-root allocation or detection-window restrictions, and it is limited due to the low cross-correlation between ZC sequences of different lengths (Xiaomi, Ericsson) [Source #12, Source #17].

Inter-cell interference, preamble reuse, or coexistence

9 sources (OPPO, Huawei/HiSilicon, Lenovo, Ericsson, NTT DOCOMO, CATT/CICTCI, Fraunhofer, MediaTek, Samsung) [Source #15, Source #1, Source #5, Source #17, Source #7, Source #14, Source #13, Source #3, Source #2] reported that the inter-cell interference and Type-2 false detection are mainly determined by the root-sequence pool size and reuse distance, which are reduced with short sequence formats and with increased preambles per RO, and that coexistence of new/non-ZC sequences with legacy NR ZC can degrade false detection relative to NR ZC with itself.

With inter-cell interference, preamble reuse, and coexistence,

  • 5 sources report that root-sequence reuse increases with the number of preambles per RO and with short formats (OPPO, Huawei/HiSilicon, Lenovo, Ericsson, NTT DOCOMO) [Source #15, Source #1, Source #5, Source #17, Source #7]. One source reported that 64 preambles require 22 roots per cell at 1.4 km radius (Lenovo) [Source #5]. One source reported that the root sequences are sufficient for only one or three cells for 1024 or 512 preambles per RO with 500 m ISD (Ericsson) [Source #17]. At most 8 roots per cell are needed for 128 preambles per RO with 4 km cell coverage;

  • 2 sources report that Type-2 false detection is reduced with larger pool size or cyclic shift spacing, e.g., 0.07%~0.09% for large pools compared to ~0.9%~7.9% for small pools, and ~3% reduced to 0.3% when the cyclic shift spacing increases from 13 to 93. One of these sources reported that a dual-sequence design with a per-cell cover code reduces Type-2 false detection by 13.7~18.1 times (CATT/CICTCI, Ericsson) [Source #14, Source #17];

  • 3 sources report the coexistence of new sequences with legacy NR ZC, e.g., median cross-correlation of 0.20~0.22 compared to 0.15 for NR ZC, and a legacy NR ZC receiver false detection of 0.8%~2.1% (8~21 times the target) with a 6 dB stronger aggressor, with the candidate's missed detection degraded by 2.1~3.1 times (Ericsson, CATT/CICTCI) [Source #17, Source #14]. One source reported that EZC-HW and Gabor-frame based sequences remain well separated from the NR PRACH pool, with maximum normalized cross-correlation below 0.28 (L=139) and 0.13 (L=839), while for ZC and NR PRACH, the maximum normalized cross-correlation reaches 1 (Fraunhofer, Huawei/HiSilicon) [Source #13, Source #1]; One Source report that regarding the cross-correlation properties with respect to NR ZC, EZC#2 is reported to outperform EZC#1, which in turn outperforms the QPSK-modulated M-sequence (MediaTek) [Source #3]

  • One source report that, with ±6 dB open-loop power control residual, the loaded missed detection of all families increases by 1.9~3.1 times, and NR ZC recovers to 0.04% while the other candidates stall at 4.3%~6.8% (CATT/CICTCI) [Source #14];

  • One source report that, using preamble(s) sharing among cell center region among multiple cells/TRPs can reduce the root sequence reuse and improve the preamble reuse. The preamble consumed by 2 cell case is reduced by 25% and 18.8% depending on the size of preamble sharing. The preamble consumed by 7 cell case is reduced by 42.9% and 32.1% depending on the size of preamble sharing. In addition, Path-loss attenuation protects desired-link Pmd and the false detection probability is within requirement when sharing preamble in convex area of two adject cells. (Samsung) [Source #2] When 32 preambles are shared with cell-center UEs in neighboring cell, the miss detection performance of the serving cell is not impacted. The number of root sequences required for the cell is reduced due to preamble reuse. (OPPO) [Source #15]

  • One resource reported that the NR restricted set B reduces the overall RACH capacity by over 95% compared to the unrestricted set, leaving a preamble reuse factor of approximately 5%. (MediaTek) [Source #3]

NTN preamble detection under timing/frequency uncertainty

8 sources (ST Engineering iDirect, CATT/CICTCI, Samsung, MediaTek, Apple, Nokia, Ericsson, Qualcomm) [Source #21, Source #14, Source #2, Source #3, Source #4, Source #18, Source #17, Source #8] reported that the existing NR PRACH formats have limited differential delay and Doppler tolerance, and that GNSS-less/GNSS-resilient NTN scenarios require robustness to the worst-case Doppler and timing error jointly, which the NR design cannot cover. The performance depends on the sequence design, the number of receiver timing/frequency hypotheses, and the satellite band.

With NTN timing/frequency uncertainty,

  • 2 sources provided analyses of the timing/frequency tolerances, e.g., NR PRACH differential round-trip delay tolerance of up to 65.9 us (format C2) and 683.6 us (format 1), and Doppler limit of up to 5.85 kHz (long format, restricted set B) and 114 kHz (short format, 120 kHz SCS), compared to required tolerances of 2903.8 us/15.444 kHz for S band and 1813.2 us/128.65 kHz for Ka band in GNSS-less scenarios (ST Engineering iDirect, CATT/CICTCI) [Source #21, Source #14];

  • One source report that format B4 with 30 kHz SCS and receiver-side multiple timing hypotheses achieves 1% missed detection at ~-14 dB for S-band LEO GNSS-less/free cases (Samsung) [Source #2];

  • One sources report that, at 2 GHz, a two-sequence NR ZC based preamble outperforms the QPSK-modulated m-sequence by ~1 dB and EZC#1 by ~1.6 dB. (MediaTek) [Source #3]

  • One resource report that non-ZC and hierarchical ZC+non-ZC sequences perform consistently with FO up to 10.5×SCS, while bi-root ZC is 1.8 dB~6.1 dB worse than the non-ZC sequence at 1% missed detection (Apple) [Source #4];

  • One source report that, with GNSS-assisted timing/frequency pre-compensation, the existing format B4 can be reused at 2 GHz with robust detection performance for 8 UEs under the residual NTN timing (13.3 µs) and Doppler (±4.18 kHz) uncertainty (Nokia) [Source #18];

  • One source report that, in a GNSS-degraded LEO600 scenario at 2 GHz (286.6 µs differential delay, ±8.44 kHz Doppler), the tone-assisted format 1A reaches 1% missed detection at ~-16.4 dB~-16.5 dB for NR ZC, Gold and cubic ZC without frequency hypotheses, ~3 dB better than Gold/cubic ZC in format 1 with a -8:1:8 hypothesis grid (-13.7 dB), with Type-1 false detection of 0.17%~1.5% compared to 1.3%~14.4% in format 1. With multiple UEs, unrestricted NR ZC suffers from Doppler de-rotation-induced peak aliasing and timing-error misses, which is resolved by using 8 distinct roots without cyclic shifts, making its missed detection comparable to Gold and cubic ZC (Nokia) [Source #18];

  • One source report that in GNSS-less/GNSS-resilient LEO scenario with residual delay up to 0.55 ms and Doppler shift up to 100 kHz, bi-rooted NR ZC-based preambles combined with multiple timing window hypotheses testing can achieve robust timing estimation, CFO estimation, and preamble detection for both long (0 and 1) and short format B4 in S-band (2 GHz) and Ka-band (30 GHz). In GNSS-less/GNSS-resilient GEO scenario with residual delay up to 3 ms and Doppler shift up to 200 Hz in S-band and 2 kHz in Ka-band, single-rooted NR ZC-based preambles combined with multiple timing window hypotheses testing can enable timing estimation and preamble detection for both long (0 and 1) and short format B4 (Ericsson) [Source #17];

  • One source report that similar performance of misdetection for 2 roots ZC with other non-ZC new sequences. The 2 roots ZC is reported to have dramatically low complexity detection compared with other new non-ZC sequences: (Qualcomm) [Source #8];

  • One source report that the detection complexity of the QPSK-modulated M-sequence and the ZC sequence is the same in TN low-speed scenarios, while the detection complexity of the QPSK-modulated M-sequence is approximately 75% of the NR ZC in TN HST scenarios, and detection complexity increases to about 190% under NTN GNSS-resilient scenarios under the assumption of 50kHz CFO. (MediaTek) [Source #3];

PRACH transmit diversity / transmit-port schemes

One source reported that PRACH transmit diversity can improve PRACH coverage in power-limited scenarios and reduce UE transmit power in non-power-limited scenarios. The gain depends on the number of receive antennas, the receive array architecture, and the TX antenna positions (Apple) [Source #4].

With PRACH transmit diversity,

  • One source report that two-port SCTD provides ~3 dB (2Rx) and ~2 dB (4Rx) SNR gain with TDL-C at 7 GHz and 3 km/h, ~0.8 dB~9 dB with a fully-beamformed receive array and up to ~5 dB with a partially-virtualized receive array at 1% missed detection; small delay CDD deteriorates the UL timing estimation accuracy (Apple) [Source #4];

Receiver algorithm used for evaluations by sources

Companies reported the following receiver algorithms/assumptions and false alarm definitions (Option 1: false alarm counted per preamble sequence; Option 2: single false alarm event counted per RO) for the preamble sequence evaluations:

  • Source #1 reports PDP-based detection (frequency-domain element-wise multiplication with each local sequence followed by IDFT), with the detection threshold based on the total received power (compared against thresholds based on noise variance only and on measurement outside the window around the detected peak), at a target false alarm probability of 0.1%; false alarm counted per RO (Option 2) (Huawei/HiSilicon) [R1-2607465];

  • Source #2 reports a matched-filter detector with |correlation|² non-coherently combined over repetitions and Rx branches and normalised by noise variance (with variants using coherent combining over repetitions after CFO compensation, non-coherent combining across ROs, delay-Doppler/GLRT and multi-peak receivers), and a noise-only threshold derived for 0.1% false alarm over the full lag × root × CFO-hypothesis search space, fixed per receiver configuration, plus a peak-to-median prominence gate for multi-UE cases; false alarm counted per RO (Option 2) (Samsung) [R1-2607561];

  • Source #3 reports a threshold normalised by a noise floor estimated as the median of the non-peak samples in the N_CS-wide delay bin and set for 0.1% false alarm, non-coherent combining of sidelobes with the main peak for restricted sets A/B, frequency-hypothesis search (½-SCS bins) only for the QPSk modulated M sequence and EZC#1, and no prior knowledge of the number of UEs per RO; false alarm counted per RO (Option 2) (MediaTek) [R1-2607901];

  • Source #4 reports a detection metric T_c = P_c / (I_c + w·P_max), where P_c is the correlation peak of code c, I_c is the largest correlation of code c outside a guard window around its peak (capturing noise plus inter-code leakage), and P_max is the strongest peak in the RO weighted by a near-far factor w; the threshold is set by noise-only Monte-Carlo simulation for 0.1% false alarm per RO, calibrated per number of preambles per RO and reused unchanged for any number of contending UEs; false alarm counted per RO (Option 2) (Apple) [R1-2608216];

  • Source #5 reports a time-domain matched filter over the full preamble burst for every candidate preamble, with detection metric Λ = ΣP/ΣN (correlation peak over average correlation outside a ±W lag window, non-coherently combined across roots; repetitions combined coherently or despread with the OCC), and the threshold found by iterative search to meet the target false alarm probability, calibrated separately per scheme, PRACH format, candidate pool size and decision mode; false alarm counted per RO (Option 2) (Lenovo) [R1-2608169];

  • Source #6 reports frequency-domain correlation and IFFT to obtain the PDP, with multi-window search and sidelobe energy combining for NR ZC with restricted sets A/B, and a frequency-offset hypothesis bank with per-tap max combining for EZC/QPSK m-sequence/Gold, using a fixed threshold for 0.1% false alarm based on thermal noise only or on thermal noise plus interference estimation; false alarm counted per RO (Option 2) (vivo) [R1-2607341];

  • Source #7 reports frequency-domain correlation per Rx and repetition, PDP derivation with non-coherent combining across Rx and repetitions, and peak detection within the detection window, with the threshold for 0.1% false alarm determined based on noise variance; false alarm counted per RO (Option 2) (NTT DOCOMO) [R1-2608348];

Notes on evaluation results reported by sources

The evaluation results reported by sources may be different due to several factors, such as receiver algorithm used, and simulation assumptions. Evaluation results across various sources reported that miss detection and false detection performance to be dependent on receiver algorithm used, especially on how cross correlation between preamble sequences is handled and detection threshold strategies used. Different sources have used different simulation assumptions for some evaluations which may also account for differences in reported performance metrics for evaluated candidate sequences and evaluated preambles.

Observation

Initial observations on number of preamble per RO evaluations. The following observations may be further updated based on additional inputs from companies in future meetings. Whether/how to capture the following observation(s) to TR is separately discussed

The following is a summary of company observations/proposals on increasing the maximum number of preambles per RO beyond 64:

Justification and use case for the capacity increase

  • 6 sources reported that the motivation for a significant capacity increase is unclear. Their points: the 6G connection density requirement is the same as 5G; field statistics show Msg4 contention-resolution failure is very low in 5G even with fewer than 64 preambles per RO; and preamble partitioning should not be the reason to increase the number of preambles, given RAN2 guidance (Xiaomi, Qualcomm, Ericsson, Samsung, NTT DOCOMO, ZTE/Sanechips) [Source #12, Source #8, Source #17, Source #2, Source #7, Source #16]. Two source reported that, with 48 additional preambles per RO for massive IoT, and 4 RO per 10ms, the collision probability is only 0.104%~0.794% for 20~153 access attempts per second per cell which correspond to IoT traffic model in TR 37.910, 6G IoT device density in 38.914, and 500m/1732m ISD (Ericsson) [Source #17]; and with 52 preambles per RO, for 1600 access requests per second the collision probability is only 1.07%, and for 400 access requests per second the collision probability is merely 0.28%.(ZTE) [Source #16]. One source reported that, for example, λ = 100 attempts/s and p = 1% require at least 156 usable ROs/s (easily supported even by existing RO configuration) (Samsung) [Source #2]; One source reported that, with 60 preambles per RO and 4 ROs per 20 ms for massive IoT, assuming 1 RACH attempt per 2 hours per UE, the collision probability is 0.11% and 1.21% for the ISD of 500 m and 1732 m, respectively (NTT DOCOMO) [Source #7]. One source reported that, with the 6G agreed assumptions on Massive Communication (IoT) to calculate the load model and access rate per cell, the collision probability calculation for different use cases is all low for 6G Massive Communication (IoT) scenarios (Qualcomm) [Source #8].7 sources reports the motivations to have preamble capacity increase. These are short formats, RACH partitioning and Msg1 information indication, multi-beam/SSB indication, PRACH repetition consuming ROs, massive connection density (e.g., the IMT-2030 target of 10^6 devices/km2), and TDD/clustered ROs that limit RO density (Huawei/HiSilicon, OPPO, LG Electronics, EURECOM, Lenovo, IIT, CATT/CICTCI) [Source #1, Source #15, Source #20, Source #22, Source #5, Source #11, Source #14]. One source reported that 64 preambles remain sufficient for steady-state eMBB, while dense mMTC needs ~550 preambles at a 1% collision target, and that preamble-pool fragmentation by SSB/feature groups exceeds 64 in most combinations (Lenovo) [Source #5];

  • 4 sources reported collision benefit of a larger pool. With 64 preambles, the 1% collision probability is exceeded at ~10 users per RO, and at two contending UEs per RO (Msg1 retransmission floor of 1.29%, against 0.69% with 128). Expanding the pool from 64 to 1024 reduces collision from ~10% to 0.1% at 32 users per RO, with diminishing returns at larger pools. With 8 UEs and 64 preambles, the collision-free probability is 63% (IIT, Apple, Nokia, Jio) [Source #11, Source #4, Source #18, Source #9]. One source reported that 128 preambles per RO or two FDM ROs give the same attempt-rate bound, ~129 attempts/s/cell at 1% collision (Jio) [Source #9]. One source report that collision-driven Msg1 retransmission floor dominates operations and it outweighs both the sensitivity cost and the false-detection cost of a larger pool, so that the total cost per successful access decreases monotonically as the number of preambles per RO increases from 64 to 256 (Apple) [Source #4];

  • One source reported for IoT traffic model in TR 37.910 and density of 10^6 devices/km^2 with ISD of 1732m and 500m that increasing RO density achieves similar reduction in Msg1 collision probability as increasing the number of preambles per RO, while reducing random access delay and avoiding MDR increase due to multi-user interference with minimal UL resource utilization. Increasing the number of preambles per RO beyond 64 reduces the collision probability, but provides only limited random access delay reduction. The source report that for the considered traffic model, Msg1 collision is not the dominant bottleneck, as random access delay is primarily driven by RO density and subsequent RA procedure steps (Msg3/Msg5) (Nokia) [Source #18].

Root-sequence pool, inter-cell reuse, and Type-2 false detection

  • 10 sources reported that increasing the number of preambles per RO consumes more cyclic shifts and/or root sequences, which increases inter-cell root reuse and Type-2 false detection, especially with short sequence formats and dense deployments (Xiaomi, Ericsson, Lenovo, Huawei/HiSilicon, Apple, NTT DOCOMO, Rakuten, CATT/CICTCI, LG Electronics, OPPO) [Source #12, Source #17, Source #5, Source #1, Source #4, Source #7, Source #24, Source #14, Source #20, Source #15]. Examples:

    • with short sequences and 500 m ISD, root sequences for 1024 or 512 preambles per RO suffice for only one or three cells without reuse; reducing from 64 to 32 preambles lowers the highest Type-2 false detection from ~5% to ~3% (Ericsson) [Source #17];

    • at 1.4 km radius with the 30 kHz short format, 64 preambles need 22 roots per cell, so a six-cell plan consumes 132 of 138 roots. The supportable count is limited to 138 (three-cell plan) and 69 (six-cell plan) (Lenovo) [Source #5];

    • the inter-cell reuse factor falls below 30 for several NR ZC formats at 1~4 km cell range, so an increase beyond 64 would need new preamble formats/sequences (Huawei/HiSilicon) [Source #1];

    • in contrast, one source reported that with 4 km coverage and 91 cells, at most 8 root sequences per cell are needed even with 128 preambles per RO, so no root reuse is needed (OPPO) [Source #15];

Detection performance (missed detection and Type-1 false detection)

  • 9 sources reported that missed and/or Type-1 false detection degrade as the number of preambles per RO increases, particularly under multi-UE and high-SNR conditions. One of them reported a large missed-detection gap from 64 to 512 preambles, translating into a coverage gap, and a worse impact for new sequences than for ZC. Another reported that for 8 users, from 64 preambles per RO to 1024 preambles per RO, for high SINR region, type 1 false detection rate degrades from ~7% to ~70%, which means 70% of preambles are falsely detected, causing 70% of resource waste to schedule 70% useless Msg 2/3, which is a big waste for the system. One source reported that a missed-detection gap of about 0.5 dB from 64 to 256 preambles per RO. Another reported that a noise-calibrated threshold yields 94.37% (64) and 99.15% (128) probability of at least one false preamble under load (Xiaomi, ZTE/Sanechips, vivo, Qualcomm, Panasonic, Ericsson, Jio, Lenovo, MediaTek) [Source #12, Source #16, Source #6, Source #8, Source #23, Source #17, Source #9, Source #5, Source #3];

  • 2 sources reported a small detection impact. With the threshold calibrated to a per-RO false-alarm budget, false detection is 0.036%/0.040%/0.045% per RO at 64/128/256 preambles, and the single-UE 1% MDR SNR increases by only 0.12 dB (64→128) and 0.22 dB (64→256) , while the aNB transmittion of Msg 2 due to false detection is at most 0.00024 wasted Msg2 per successful access, which remains two to three orders of magnitude below 0.4%~10% Msg1 retransmissions per successful access (Apple) [Source #4]. Type-1 false detection does not increase with identity count when identities are created by coding across two sequence segments (CATT/CICTCI) [Source #14];

Complexity, latency, and procedure impacts

  • 5 sources reported further impacts of increasing the number of preambles per RO: increased BS detection complexity, longer random access latency, increased UE Msg2 detection effort, and a trade-off with Tx/Rx complexity and capability (Ericsson, Panasonic, Nokia, KTL, Qualcomm) [Source #17, Source #23, Source #18, Source #10, Source #8];

  • One source reported that with new non-ZC sequence for increasing the number of preambles per RO, it will have new hardware implementation requirements e.g. to implement non-standard DFT size, which will cause additional implementation hardware cost, timeline and complexity (Qualcomm) [Source #8].

  • One source reported that a larger pool moves the bottleneck to RAR capacity, and that 128 preambles per RO need a 7-bit preamble identity or an equivalent preamble-group context in the response, requiring RAN2 coordination (Jio) [Source #9];

Alternatives to increasing the number of preambles per RO

  • 9 sources proposed adding ROs in time and/or frequency, or adapting them, as the first or preferred means to increase capacity. Examples are Rel-19 on-demand RO adaptation, FDM ROs sharing the preamble pool, and fixed-64 RO offloading as a reference. Adding ROs reduces the load per RO without increasing root demand, at the cost of UL resource overhead, MsgX scheduling additional ROs to resolve collision to operate with higher access capacity (Nokia, Xiaomi, OPPO, Ericsson, Lenovo, Jio, Korea Testing Laboratory, NEC, Tejas, Qualcomm) [Source #18, Source #12, Source #15, Source #17, Source #5, Source #9, Source #10, Source #25, Source #26, Source #8];

  • 3 sources proposed other mechanisms: conveying Msg1 information without partitioning the contention-based preamble pool (Lenovo) [Source #5], and reserving smaller cyclic-shift ranges for UEs with a valid timing advance to save root-sequence resources (Rakuten) [Source #24]; and preamble(s) sharing among cell center region among multiple cells/TRPs to reduce the root sequence reuse. The preamble consumed by 2 cell case is reduced by 25% and 18.8% depending on the size of preamble sharing. The preamble consumed by 7 cell case is reduced by 42.9% and 32.1% depending on the size of preamble sharing.(Samsung) [Source #2]

  • Adopt 4-step RACH as the baseline procedure for 6GR.

  • Question 1 (whether it is possible to support 2-step and 4-step RA when they are both configured with the same preamble and RACH occasion):

    • RAN1 has not yet studied 2-step RA design and not yet assessed feasibility for 6GR. RAN1 has identified at least the following aspects based on 5G NR 2-step Preamble and MsgA:

      • The gNB attempts PUSCH reception for a detected preamble and falls back to 4-step RA when the PUSCH is not successfully received, which increases the number of blind PUSCH detections at the gNB.

      • If 4-step RA is configured together with 2-step RA, the response for a 4-step RA UE may need to be delayed until after the PUSCH occasion, which may increase 4-step RA latency and/or reduce the resources available for RAR transmission within the response window.

      • Distinguishing which procedure a UE has initiated is not deterministic from the preamble alone, which has implications on RAR/fallback handling.

  • Question 2 (for 2-step RA, whether it is necessary to have correspondence between PRACH and PUSCH transmissions in MsgA, and if so how to establish it):

    • From RAN1 perspective, correspondence is necessary, at least for the following functions based on 5G NR 2-step Preamble and MsgA:

      • determination of the PUSCH resource associated with a detected preamble,

      • PUSCH scrambling and multiplexing of UEs sharing an RO,

      • timing-advance handling, and identification of the UE in the fallback RAR.

    • Note that RAN1 has not made any agreements on physical signals/channels of 2-step RA for 6GR and applicability of correspondence is currently undetermined.

  • Note: RAN1 will continue the study of the above aspects and will inform RAN2 if the answers need to be updated.
