Observation:

For the channel-coding candidate option(s) for small UCI payloads of 3–11 bits, more details on the corresponding design are provided below.

  • Option S1: 5G RM code

  • Option S2: Enhanced RM code with maximum mother code length of 32, e.g., by one of the following

    • sequence selection for encoding (Xiaomi R1-2607200, ZTE R1-2605783)

    • reuse NR RM code, with enhanced interleaver(s) for rate matching (vivo R1-2607336, ZTE R1-2608669, CATT R1-2608644, Ericsson R1-2607973, Qualcomm R1-2608414, Google R1-2608468, 1Finity R1-2607618)

    • enhanced encoding matrix with enhanced interleaver(s) for rate matching (Apple R1-2606019)

    • enhanced encoding matrix (Xiaomi R1-2607200)

  • Option S3: Enhanced RM code with extended maximum mother code length, e.g., 64, 128

    • Extended RM code (up to (128, K)) using NR RM as the base code for 7≤K≤11, based on information block size (A) and number of coded bits (E) value. Note (32, K) would be the NR RM code. (See details in Ericsson R1-2607973)

      • See example design in [Huawei R1-2608659]

    • Using NR PC-Polar code chain with the following differences

      • predefined pre-frozen/PC bit(s)

      • mother code length determination

      • [For different K and E combinations, the above configuration may be different.]

      • See example design in [Apple R1-2608244]

    • Using NR PC-Polar code chain with the following differences

      • predefined pre-frozen/PC bit(s)

      • no CRC

      • mother code length determination

      • See example design in [MediaTek R1-2607896]

    • Extended PC-Polar code for small UCI with 3~11 bits without CRC (Qualcomm R1-2608414)
