Agreement:

Further clarify the radial velocity, in case EO type-2 is involved, as marked in red:

The true radial velocity is the sum of the following two components:

  • Component 1: The projection of the velocity difference vector on the unit-norm vector from target to STX, where the velocity difference vector is between the true 3D velocity of the target and the true 3D velocity of the STX;

  • Component 2: The projection of the velocity difference vector on the unit-norm vector from target to SRX, where the velocity difference vector is between the true 3D velocity of the target and the true 3D velocity of the SRX.

Note: If STx and SRx are static, true radial velocity is 2*v3D*cos(β2)*cosα, where v3D is the true 3D velocity of the target, β is the bistatic angle between incident direction and scattering direction, and α is the angle between the true 3D velocity vector and the bisector vector within the bistatic angle β. For mono-static sensing, β=0.

Note2: Optionally, in case STX-ST link is replaced by STX-EO-ST link (e.g. when STX-ST is in NLOS condition) due to specular reflection from environment object (EO), Component 1 is replaced by the sum of following two components:

  • Component 1a: The projection of the velocity difference vector on the unit-norm vector from EO to STX, where the velocity difference vector is between the true 3D velocity of the EO and the true 3D velocity of the STX;

  • Component 1b: The projection of the velocity difference vector on the unit-norm vector from target to EO, where the velocity difference vector is between the true 3D velocity of the target and the true 3D velocity of the EO;

Note3: Optionally, in case ST-SRX link is replaced by ST-EO-SRX link (e.g. when ST-SRX is in NLOS condition) due to specular reflection from environment object (EO), Component 2 is replaced by the sum of following two components:

  • Component 2a: The projection of the velocity difference vector on the unit-norm vector from target to EO, where the velocity difference vector is between the true 3D velocity of the target and the true 3D velocity of the EO;

  • Component 2b: The projection of the velocity difference vector on the unit-norm vector from EO to SRX, where the velocity difference vector is between the true 3D velocity of the EO and the true 3D velocity of the SRX.

Agreement:

For Rel-20 6G ISAC performance evaluation, for object detection and/or tracking:

The FAP type 1 (false alarm probability type 1) is calculated as follows:

  • False alarm probability Type 1 is defined for cases without true target dropped in simulation area. An object detected when there is no target present in the simulation area is considered a false alarm.

Pf1=∑n=0N−1QnN

where,

- Qn is equal to 1 if at least one object is detected when there is no target dropped in the simulation area in the drop n, otherwise Qn is equal to 0.

- N is the total number of drops without target in the simulation area.

The horizontal/vertical positioning accuracy is defined as follows:

  • Horizontal/vertical positioning accuracy is defined as the absolute value of the difference between the estimated horizontal/vertical position and the corresponding true position of a sensing target.

Note: The value of horizontal/vertical positioning accuracy and the velocity accuracy shall be obtained assuming 90% confidence level, which is the 90th percentile point of the CDF of the location estimation error.

R1-2607430 Moderator summary #2 on ISAC evaluations Moderator (CATT)

Agreement:

For Rel-20 6G ISAC performance evaluation, for sensing assisted communication, for reporting the time-frequency resource cost due to sensing for SAC:

  • Type_1: Resource that are used for sensing purpose (due to sensing for SAC)

  • Type_2: Part of Type_1 resources that are used for communication purpose

  • Type_3: Resources that are not used for sensing purpose, and cannot be used for communication purpose due to sensing operation (due to sensing for SAC)

Companies are required to report Overhead 1 and Overhead 2.

  • Overhead 1: (Type_1 + Type_3) resources over all radio DL and UL resources

  • Overhead 2: (Type_1 - Type_2 + Type_3) resources over all radio DL and UL resources

Note: If Type_2 resource doesn’t exist, two overheads are the same; if Type_1 resource = Type_2 resource, Overhead 2 is equal to Type_3 resource only, which could be zero if Type_3 doesn’t exist.

Note 2: Overhead 1 and Overhead 2 should be calculated in NW level, not single UE level.

Note 3: For some of the communication use cases, the communication resource overhead may be reduced due to sensing assistance, which will be reported separately, e.g. as performance metric of communication

Note 4: Type_2 resource shall be calculated excluding the reduced communication resource overhead if the communication resource overhead can be reduced due to sensing assistance.

Companies can report additional information/assumption on whether/how much the SAC resource can be shared with OD&T.

Note 5: This does not require companies to simulate OD&T and SAC simultaneously

Note 6: This does not imply specifying same or different RS/resource for OD&T and SAC
