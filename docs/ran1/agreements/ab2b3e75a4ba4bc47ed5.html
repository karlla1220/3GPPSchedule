R1-2607812 FL Summary #1: GNSS resilient NR-NTN operation Moderator (Thales)

Agreement:

For GNSS-resilient NR-NTN initial access based on the transmission of two PRACH sequences using the same existing PRACH format and different roots (Alt 1-4), RAN1 to down-select one of the following alternatives:

  • The transmission of the two PRACH sequences is performed in separate ROs in the time domain (TDM method). The transmission of the two PRACH sequences overlapping in time and frequency within the same RO (CDM method) is deprioritized in R20 NR NTN.

  • Note: The above is decided based on the evaluation assumptions (such as LOS channel and 3 km/h) and studies during the corresponding study phase.

  • FFS: Other details

R1-2607814 FL Summary #3: GNSS resilient NR-NTN operation Moderator (Thales)

Agreement:

For the selection of the two root sequences in a dual PRACH transmission, RAN1 to specify a root-pairing mechanism. RAN1 to down-select one of the following options for the mechanism:

  • Option A: Fixed/derived rule: The relationship between u1 and u2 is defined by a single, mathematical rule. Candidate rules include:

    • Option A-1: Inverse-Root Offset (Unit-Shift): u2−1=(u1−1+s)modLRA

    • Option A-2: Logical Index Offset: e.g., i2 = (i1 + k) mod NG or i1=istart+((i2−istart+2)modNG)

    • Option A-3: Root-Group Offset: i2=2((⌊i1/2⌋+Δg)modNg)+1−(i1mod2)

    • Option A-4: ku1 = (k+1)u2 mod LRA, where k is an integer

  • Option B:

    • Table-Based selection: The gNB signals an index or set of parameters that points to pre-defined table(s) of optimized root pairs.

      • Option B-1

        • Two tables are specified (for long and short preamble formats, respectively) with root pairs (μ1,μ2) selected to provide minimum CM difference within each pair while satisfying the root selection criterion 2C<|q|<(N−2C)/2, where q=fold((μ1−1−μ2−1)−1modN), N is the ZC sequence length and C is the maximum CFO normalized with respect to the subcarrier spacing. The root pairs in the tables are further ordered by ascending pair CM (defined as the max CM of the two roots in a pair).

        • The network indicates a starting logical root pair index from which the UE can extract up to 64 consecutive logical root pair indices from the applicable table.

        • Root pair tables (for evaluation purposes) are given in appendix B of R1-2608710, R1-2607250

  • Option C: Configured by NW:

    • Option C-1:

      • Use starting logical index i1 for the first root sequence and starting logical root index i2 for the second root sequence, using existing rules for preamble generation per RO

      • NW configure i1 and i2

    • Option C-2:

      • Use starting logical index i1 for the first root sequence and starting logical root index i2 for the second root sequence, root pair validation based on condition until determine 64 preamble pairs, where the condition is:

        • if the minimum Distance (Dmin) of a root pair is greater than d , the root pair is valid, otherwise the root pair is invalid.

        • the Dmin is calculated as Dmin(s) = min-Kmax ≤ m ≤ Kmax circ_dist(m·s, L), where

s = (u1-1 − u0-1) mod L, and circ_dist(x,L) = min(x mod L, L − (x mod L)), Kmax is 7, L is ZC sequence length, the value d is configured or pre-defined.

  • NW configure i1 and i2

  • Option D:

    • NW configure root pair list, where each entry of the list is a pair of root (u1,u2).

Companies are encouraged provide evaluation if relevant for MDR, CM/PAPR, time/frequency estimation errors and signaling overhead, inter-cell PRACH interference, etc.

  • The exact parameters, value ranges, and signaling for the chosen mechanism (e.g., values for s or k, or the design of the tables).

  • The handling of the cyclic shift for the first and second PRACH transmission.

  • The impact on required number of correlators per RO, considering the RO pairing mechanism that will be used.

Agreement:

RAN1 to down-select one of the following granularity frameworks for the FAC in Msg2:

  • Option 1: SCS-based Granularity (WF1): The FAC granularity is defined relative to the subcarrier spacing.

    • FAC_granularity = SCS / 2k

    • k = [8]

    • Note : The FAC is applied as an offset to the nominal UL carrier frequency f0 derived from uplink config.

  • Option 2: PPM-based Granularity (WF2): The FAC granularity is defined as an absolute value in ppm

    • X = [0.01] ppm

  • Option 3 (compromised): SCS-based Granularity (WF1): The FAC granularity is defined relative to the subcarrier spacing.

    • FAC_granularity = SCS / 2k

    • k is selected such that the granularity when converted to ppm is less than 0.01 ppm.

    • Note : The FAC is applied as an offset to the nominal UL carrier frequency f0 derived from uplink config.

R1-2607815 FL Summary #4: GNSS resilient NR-NTN operation Moderator (Thales)

Agreement:

For of dual PRACH transmission attempt:

  • One RACH attempt consists of one " RO pair " or more than one RO pair (in case PRACH Repetition is used):

    • an "RO-Pair" is consisting of two valid ROs to accommodate the dual PRACH transmission.

      • FFS: Whether the “RO pair” will be defined in the specs

    • The RO-pair is located on the same frequency resources.

    • The two ROs in the pair occupy different time-domain resources.

    • FFS: How to perform Dual PRACH transmission with repetition

    • FFS: configuration details

Agreement:

  • RAN1 to discuss and to down-select one of the following alternatives for determining the temporal relationship between the two ROs of one RO-pair, when the PRACH repetition is not used:

    • Alternative 1: Consecutive ROs: The two ROs are two consecutive valid ROs in the time domain, based on the PRACH configuration index/a SSB.

      • “Valid ROs” per existing specs is the baseline.

      • FFS: Whether additional rule to validate RO for dual PRACH transmission should be defined

    • Alternative 2: Configurable offset: The second RO is located at a configured time offset relative to the first RO.

      • First RO is configurated per the current specs (based on PRACH config index), and

      • The second RO is the newly added RO which determined based on the configurable offset, and 

      • The offset is set to be larger than zero, and

      • First RO of the RO-pair is a “Valid RO” per existing specs

      • FFS: Whether/how to determine the validity of second RO

  • Whether to support/configure separate/shared RO resources for GNSS-resilient UEs is discussed in a separate proposal.

  • SSB-to-RO mapping rules will be discussed in a separate proposal

Agreement:

For handling of TA over-compensation (i.e., the UE's signal arrives earlier than expected) in initial access for GNSS resilience operation, support the following:

  • Introduce a TAC field in the MAC RAR to directly indicate positive or negative timing corrections relative to the UE's open-loop pre-compensated transmission.

  • Introduce a higher-layer configured TA offset. The UE additionally applies this offset to all UL transmissions to bias its timing, if TA offset is configured in SIBx.

    • FFS: Granularity and value range for TA Offset

    • FFS: Whether TA Offset is configured per beam or cell

    • Note: The higher layer TA offset can be configured to avoid TAC value received in Msg2 is negative

Agreement:

The Frequency Adjustment Command (FAC) in connected mode is indicated explicitly via a new MAC CE 

  • Details of the MAC CE structure to be coordinated with RAN2.

The closed-loop frequency control utilizes an accumulative (relative) adjustment mechanism as the baseline.

  • Baseline principle: The UE updates its closed-loop frequency adjustment state by adding the relative delta value indicated in the FAC MAC CE to its current state.

FFS:

  • The range for the relative FAC in the MAC CE

  • UE behavior regarding the accumulated FAC/TAC state upon a change in the open-loop pre-compensation reference or satellite handover (e.g., retain, rebase, or reset).

Agreement:

For TA control in RRC_CONNECTED for GNSS-resilient NR-NTN operation, RAN1 to discuss and down-select one of the following for the implicit TA drift compensation:

  • Option 1: Explicitly define the mathematical formulas (e.g. NTA(t)=NTA(t0) + TAdrift ×(t−t0)) and the exact reference time (t0​) in the 3GPP specifications (TS 38.211 / 38.213).

    • FFS: How to derive TA drift from the FAC.

  • Option 2 (UE Implementation): Leave the specific derivation of TA drift from the FAC and its continuous application up to UE implementation, provided the UE meets applicable RAN4 performance requirements.

FFS:

  • State management upon command reception or reference change: The exact UE behavior (e.g., retain, rebase, or reset to zero) for the accumulated TA, FAC, and TA drift states upon reception of a new TAC/FAC or when the open-loop compensation basis changes (such as a change in the network-indicated reference location or during a satellite handover).

R1-2607816 FL Summary #5: GNSS resilient NR-NTN operation Moderator (Thales)

Agreement:

For GNSS-resilient open-loop UL time/frequency pre-compensation in a (quasi) Earth-fixed cell, the target granularity in longitude/latitude of each beam/cell reference location should be ≤X,

  • X= 20m

  • X= 50m

  • X=150m

Select one of the above X values

FFS: impact of these values on timing/frequency performance

FFS: value ranges (absolute and relative)

Note: Other values of X are not precluded.

Note: This doesn’t prevent reusing the granularity of the existing referenceLocation-r17.

Note: the number of SSB beams as per the existing specs.

Working assumption

The value range for TAC in msg2 should cover at least this range: [ -2903.6 µs .. +2×2903.6 µs]

  • Note: Range reduction can be considered.

Working assumption

The target value range for FAC in kHz in RAR (msg2) should cover at least: [ -127.08 kHz .. + 127.08 kHz]

  • These values apply at least for the Ka band.

  • FFS whether other bands will have a smaller absolute range

The target value range for FAC in connected mode should cover: [-60 kHz ..+60 kHz]

  • These values apply at least with 120 kHz SCS

  • FFS whether other SCS will have a smaller absolute range

Agreement:

For PRACH configuration for dual PRACH transmission. Support separate PRACH configurations for Rel-20 GNSS-resilient initial access to ensure coexistence with legacy NTN UEs.

FFS: Whether/how to handle the case where RO for dual PRACH and RO for single PRACH transmission are overlapped in time and frequency.

Agreement:

Reuse the legacy SSB-to-RO mapping rules and configurations to map the selected SSB(s) to the designated RO-Pair.

Agreement:

For the dual PRACH transmission feature, where one RACH attempt consists of two PRACH transmissions in an RO pair:

  • the two PRACH transmissions are treated as a single random-access attempt.

    • Note: This implies a single preamble transmission counter increment and a single power ramping counter increment for the attempt.

  • the RAR window timing and the RA-RNTI calculation are based on the last of the two ROs in the pair.

  • no power ramping is applied between the two PRACH transmissions within a single attempt.
