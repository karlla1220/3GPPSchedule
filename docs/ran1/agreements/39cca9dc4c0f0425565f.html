Observation:

For operation in the same cell or carrier of “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation (including potential modifications introduced in the Rel-20 GNSS resilience work item)” and “UEs not performing uplink pre-compensation”, the following is observed from RAN1 perspective:

  1. For operation in the same cell (which is performing downlink pre-compensation):

    1. According to current RAN2 specifications (copied below), barring mechanisms prevent both types of UEs from operating in the same NTN cell.

      1. Based on the current specification, “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation (including potential modifications introduced in the Rel-20 GNSS resilience work item)” perform UL pre-compensation in NTN cell only.

      2. Based on current specification, an NTN cell can only be deployed in RAN4 defined NTN band.

cellBarredNTN

Value barred means that the cell is barred for connectivity to NTN, as defined in TS 38.304 [20]. Value notBarred means that the cell is allowed for connectivity to NTN. If not present, the UE considers the cell is not allowed for connectivity to NTN, as defined in TS 38.304 [20]. This field is only applicable to NTN-capable UEs. In an NTN cell, the network always includes cellBarredNTN and sets the cellBarred in MIB to barred.

  1. If the actual satellite ephemeris information is broadcast in SIB19:

    1. In the uplink

      • From RAN1 specification it is allowed two types of UE served in UL in the same cell.

      • At network reception, the timing and frequency difference between “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation (including potential modifications introduced in the Rel-20 GNSS resilience work item)” and “UEs not performing uplink pre-compensation” can be calculated by the network.

        1. NOTE: This assumes that Rel-20 GNSS resilience work item does not introduce a mechanism to align the transmission of both types of UEs.

      • For PRACH, the network would need to handle 2 timing / frequency hypotheses and would need to perform scheduling (by network implementation) to handle this timing / frequency difference. Some companies indicated that these can be handled by the network implementation, while other companies indicated that this results in increased network complexity.

      • A common TA (following Rel-17 specifications) can be indicated to “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation (including potential modifications introduced in the Rel-20 GNSS resilience work item)”, to align the slot boundaries (at the network) between both types of UEs (up to an offset equal to an integer number of slots)

        1. Some companies mention that current common TA mechanism only allows positive, quadratic terms which may increase the rate at which the UE needs to acquire SIB19.

      • After PRACH, TAC can be used to align the slot boundaries (at the network) of both types of UEs (up to an offset equal to an integer number of slots)

        1. NOTE: Separate TAC can be indicated to both types of UEs.

      • For channels other than PRACH, if the UE does not support FAC (being defined in Rel-20 GNSS resilient work item), there will be a frequency difference between both types of UEs, and the network would need to perform scheduling (by network implementation) to handle this frequency difference.

      • There will be a slot number difference between both types of UEs, which would need to be handled by network implementation. This difference will also happen among the “UEs not performing uplink pre-compensation” in case the differential delay within a cell exceeds the slot duration. Some companies indicated that these can be handled by the network implementation, while other companies indicated that this results in increased network complexity.

  1. In the downlink:

    • the Doppler (if DL Doppler is pre-compensated) and time delay variation (if DL time delay variation is pre-compensated) obtained based on the measurement of DL signals at a Rel-17/18/19 NR-NTN UE will not match the one derived based on ephemeris and GNSS location, except in some cases in which it will match (e.g. at Nadir or in a GEO satellite).

    • Some companies mentioned that the downlink reception performance before SIB19 acquisition should not be affected by DL pre-compensation since at that stage the UE has not yet acquired the ephemeris.

    • Some companies mentioned that if the Rel-17/18/19 NR-NTN UE (by implementation) makes use of the ephemeris (after SIB19 acquisition) and GNSS location for downlink tracking, this mismatch due to DL precompensation would lead to performance degradation in the downlink reception.

    • Some companies mentioned that if the Rel-17/18/19 NR-NTN UE (by implementation) solely relies on downlink signals for tracking (e.g. by using SSB/TRS every 20ms), the downlink reception performance with or without the mismatch due to DL precompensation should be comparable.

      1. Tracking based on measurement of DL signals is specified in current standards.

    • NOTE: The current specifications neither mandate nor preclude the UE from using the ephemeris for downlink tracking.

  1. If a “synthetic” ephemeris is broadcast in SIB19:

    1. A “synthetic” ephemeris consists of a position and/or velocity vector which is different from the actual one at the satellite (using existing signaling in SIB19), which may be combined with an appropriate common TA to minimize time difference (up to an offset equal to an integer number of slots) and/or frequency difference with respect to UEs not performing uplink pre-compensation. Companies have proposed different methods to create a “synthetic” ephemeris, including the following:

      • Alt 1: The position vector is the actual one, the velocity vector is not the actual one.

      • Alt 2: Both the position and velocity vectors are not the actual ones.

    2. The timing (if DL time delay variation is pre-compensated) and frequency difference (if DL Doppler is pre-compensated) between both types of UEs can be reduced. For the UEs that process this ephemeris (“UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation”), perfect UE alignment at the satellite in frequency is not possible, but the alignment can be made to be better than or equal to that of “UEs not performing uplink precompensation”.

      • Some companies observed that, for Rel-20 UEs supporting GNSS resiliency features, the “synthetic ephemeris” may be combined with Rel-20 enhancements (e.g. FAC) to reduce the frequency misalignment.

      • In R1-2608387 (ESA, Aalyria) it is proposed to use a synthetic ephemeris with actual position vector and synthetic velocity vector, combined with common TA, and an ephemeris validity duration of 5 seconds. Based on the assumed propagation model, the residual frequency errors are within (263Hz, 643Hz) for cell radius within (5km, 50km).

      • In R1-2607299 (ZTE) and R1-2608478 (Nokia), it is proposed to use a fixed satellite location with a zero velocity vector. In this case, the residual frequency error of “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation” is the same as that of “UEs not performing uplink precompensation”

    3. Some companies mention that a “synthetic” ephemeris may not comprise a valid orbit and, therefore, the effectiveness of this method may depend on the implemented ephemeris propagation algorithm (not specified in 3GPP specifications) at the UE within one validity duration. Some other companies mention that the UE should avoid propagation algorithm that are not compatible with PV state vectors and introducing additional assumption. Some other companies mentioned that the UEs should be able to manage some degree of variation with respect to nominal orbital trajectories (e.g. due to satellite maneuvering).

    4. Some companies mentioned that some “synthetic ephemeris” techniques under Alt 1 may require short ephemeris validity duration and would increase the frequency at which a UE needs to decode SIB19. Some companies mentioned that, in systems in which the UE dwell time in a cell is short, this increase might not be significant.

    5. Some companies mentioned that the “synthetic ephemeris” needs to be set in a cell-specific manner (including for cells belonging to the same satellite), which requires the network to include a separate satellite ephemeris for each neighboring cell even when the cells belong to the same satellite. Some other companies mentioned that the same overhead occurs when using actual ephemeris.

  1. For operation in the same carrier, the network can provide two cells in the same carrier (by either TDM or FDM), one for “UEs not performing uplink pre-compensation.”, and one for “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation (including potential modifications introduced in the Rel-20 GNSS resilience work item)”). In this case:

    1. In the uplink, there will be a frequency difference between both cells due to different pre-compensation behavior, requiring the network to perform scheduling (by network implementation) to handle this frequency difference.

      • For PRACH, the network would need to handle 2 hypotheses and would need to perform scheduling (by network implementation) to handle this frequency difference.

      • A common TA can be indicated to “UEs performing Rel-17/18/19 NR-NTN uplink pre-compensation (including potential modifications introduced in the Rel-20 GNSS resilience work item)”, to align the slot boundaries (at the network) between the two cells

      • After PRACH, TAC can be used to align the slot boundaries (at the network) between the two cells

      • For channels other than PRACH, if the UE does not support FAC (being defined in Rel-20 GNSS resilient work item), there will be a frequency difference between two cells, and the network would need to perform scheduling (by network implementation) to handle this frequency difference.

    2. This solution requires the network to transmit separate broadcast common channels for each of the cells. Some companies mentioned that this increases the signaling overhead by 2x with respect to a single cell solution. Other companies mentioned that, at least in the scenario where “UEs not performing uplink pre-compensation” is claimed to be deployed (e.g. 20MHz channel bandwidth), this additional overhead is negligible.

  3. Current specification allows that two types of UEs can operate in the same carrier if each type belong to a different cell in the carrier. Some companies mention that this mode of operation is not practical due to network complexity and inefficiency. Some companies mention that this mode of operation is feasible with negligible network complexity without impact on efficiency.

  1. Some companies observed that, according to the Rel-20 GNSS resilient study item, operation of “UEs not performing uplink pre-compensation” is only possible if the beam size is sufficiently small (e.g. less than 14km diameter for LEO-340). Some other companies observed that the deployment is not dependent on the beam size.

Note: The observation above made by various companies are generally qualitative assessment, not quantitative one based on specific satellite deployment scenario.
