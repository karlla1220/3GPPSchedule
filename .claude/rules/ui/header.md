# 헤더: 후원 안내, 원본 파일 줄, 제작자 줄, 회의 종료 인사, 탭 아이콘

HTML은 `shared/page.py`, 표시 판단은 `templates/support-note.js`, 값은 `site.json`의 `presentation`이다.

## 후원 안내

- **후원 요청은 시간표를 가리지 않는다.** 모달, 상단 고정 바, 그리드 안이나 사이에는 두지 않는다. 헤더 안의 두 곳(상시 안내, 회의 종료 인사)뿐이다.
- **상시 안내는 미팅 제목 줄의 오른쪽 끝이다(`.support-links`).** ☕ 옆에 두 줄: `Proposal 1: Buy a coffee for Duckhyun` / `on Patreon or GitHub Sponsors`.
  - 문구는 기고문의 `Proposal 1: …` 말투를 빌린 농담이다. 참석자만 알아보는 형식이라 구걸처럼 읽히지 않는다.
    3인칭 글이라 `me`가 아니라 이름(성 없이)을 적는다. 문구는 `site.json`의 `support_title`이고 코드에서 이름을 조립하지 않는다.
    회의 종료 인사는 1인칭 글(`I build …`)이라 `buy me a coffee`다.
  - 회사 이름이 같은 헤더에 있으므로 형편을 내세우는 문구(`Help this poor guy` 등)는 쓰지 않는다. 후원 문구에 회사 이름도 넣지 않는다.
  - 문장 전체가 이탤릭이다(`.support-text`, 기고문에서 Proposal을 이탤릭으로 적는 관례). ☕는 기울이지 않는다.
    Source Sans 3 이탤릭(400, 500)을 `schedule.html`의 `<link>`에서 불러온다. 빼면 브라우저가 정체를 기울여 흉내 낸다.
  - 글자는 `--ink`, 첫 줄과 링크는 굵기 500, 크기는 meta 줄과 같은 12px(둘째 줄 11.5px), 아이콘 22px.
    meta 회색으로 두면 눈에 띄지 않고, 14px 600에 28px 아이콘이면 미팅 제목보다 먼저 보인다. 상자나 버튼 바탕은 두지 않는다.
  - `position: absolute`다. 가운데 정렬된 제목과 그 아래 그리드의 위치가 이 블록 때문에 바뀌지 않는다. 세로로는 제목 + 상태 줄의 가운데다.
  - **화면 폭 1024px 이하에서는 제목 줄 아래 가운데 한 줄로 내려온다.** 오른쪽 형제 미팅 링크와 겹치지 않는 폭이 기준이다.
    활성 WG가 늘거나 링크 이름이 길어지면 기준을 다시 잰다. 그 한 줄은 meta 줄과 같은 크기·굵기(12px, 400)이고 색만 `--ink`다.
  - 후원 수단은 이름을 그대로 링크로 쓴다(`support_links`의 `label`). `Support` 하나에 묶으면 한 번 더 눌러야 고를 수 있다.
    회의 종료 인사도 같은 목록을 같은 순서로 쓴다. 같은 안내를 제작자 줄에 한 번 더 적지 않는다.

## 원본 파일 줄

- **이름 전체가 아니라 짧은 이름과 버전으로 적는다(`Sources: Main v03 · Hiroki v01 · Sorour v00`).**
  이 줄에서 확인하는 것은 최신 버전이 반영됐는지뿐이다. 파일 이름은 `title`(hover)에 남긴다.
  - 짧은 이름은 각 WG 파이프라인이 `Schedule.source_labels`(파일 이름 → 이름)로 넘긴다. RAN1은 `Main`과 부의장 이름,
    RAN2는 `Schedule`·`Agenda`, RAN P는 `Time plan`·`Agenda`다. 파일 이름에서 사람 이름을 추측하지 않는다.
  - 버전은 `page.py`가 파일 이름의 마지막 `v숫자`에서 읽는다. 이름이 없는 파일(예전 스냅샷, 데모)은 파일 이름 그대로 보인다.
  - Draft 파일은 버전 앞에 `draft`를 적는다(`Main draft v03`). 의장이 `Draft`를 떼면서 `v00`부터 다시 매기므로,
    숫자만 보면 뒤로 간 것처럼 보인다. Agreement 패널의 변경 줄(`· draft v01`)도 같다.

## 제작자 줄

- **맨 아래 두 줄이다.** `Created by 이름 (메일), 소개` 아래에 `면책 문구 · Feedback`.
  - 메일 주소는 그대로 적는다. `Feedback`(GitHub Issues)만 두면 계정이 없는 참석자는 연락할 방법이 없다.
  - 헤더 meta 링크는 meta 회색을 그대로 쓰고 밑줄로만 구별한다. 소속은 제작자 소개(bio)에만 쓴다.

## 회의 종료 인사

- **회의 마지막 날 정오(회의 시간대)부터 보인다.** 고마움을 느끼면서 아직 페이지를 여는 때가 마지막 날 오후다.
- ℹ️ 안내문 바로 아래, 그리드와 같은 표면(흰 바탕, 헤어라인 그림자, `--radius-lg`)이고 글 길이만큼만 차지한다.
- ☕는 링크 밖에 두고 `&nbsp;`로 붙인다. 링크 안에 두면 밑줄이 이모지까지 이어지고 좁은 화면에서 이모지만 다음 줄로 떨어진다.
- **보일지는 브라우저가 정한다.** 페이지는 일정이 바뀔 때만 다시 만들어지므로, 만든 시점의 상태를 HTML에 넣으면 틀린다.
- 스크립트는 인사 바로 뒤에 인라인으로 둔다. 그리드가 그려지기 전에 실행되어 보고 있던 화면이 밀리지 않는다.
- 닫으면 회의마다 한 번만 기억한다(`localStorage`, 키에 `wg_id:meeting_id`).
- 더미 미팅, 끝나는 날을 모르는 회의, `support_links`가 없는 사이트에는 넣지 않는다.

## 탭 아이콘

`templates/favicon.svg` 하나이고, `renderer.py`가 `<link rel="icon">`의 data URI로 넣는다.

- **달력 + 굵은 `3` + 빨간 전파 호 두 개다.** 달력은 일정을, `3`과 호는 3GPP를 가리킨다.
  - 3GPP 로고는 쓰지 않는다. ETSI의 상표이고, 헤더에 "Not affiliated with … 3GPP"라고 적은 페이지다.
  - `3GPP` 네 글자는 16px에서 뭉개진다. `3G`는 3세대 이동통신으로 읽힌다.
- **16px에서 먼저 확인한다**(고해상도 32px). 밝은 탭과 어두운 탭 모두에서 본다. 흰 몸통의 회색 테두리는 밝은 탭에서 윤곽을 지킨다.
- 글자는 path가 아니라 시스템 글꼴(Arial 계열, 900)이다. 파비콘 SVG는 웹폰트를 불러올 수 없다.
