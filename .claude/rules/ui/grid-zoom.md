# 그리드 핀치 줌

- **그리드 위의 핀치는 페이지가 아니라 그리드를 줌한다(CSS `zoom`, `--grid-zoom`).** 휴대폰에서 하루 전체를 한눈에 보려고 둔다.
  - 그리드는 자기 상자(`.grid-wrapper`) 안에서 가로로 스크롤되므로 페이지는 화면보다 넓지 않고, 브라우저는 페이지 폭 아래로 줌아웃하지 않는다.
  - 페이지 자체를 넓히는 방법은 버렸다. Chrome(삼성 인터넷 포함)은 레이아웃 뷰포트를 페이지 폭으로 넓혀서,
    sticky인 시간 열과 방 이름, 오른쪽에 고정된 Filter 탭이 화면 밖으로 밀려난다.
  - 상자가 그대로라서 시간 열 sticky와 팝업 위치 계산이 바뀌지 않는다. 팝업과 Filter는 그리드 밖이라 줌되지 않는다.
- **범위는 하루가 화면 폭에 맞는 배율(`.grid-wrapper` 폭 ÷ `--grid-min-width`)부터 2배까지다.**
- **100%에서 한 번 멈춘다(`GRID_ZOOM_DETENT`).** 핀치가 100%를 지나면 손가락 간격이 15% 더 바뀔 때까지 100%에 머문다.
  100%가 셀 디자인의 기준이라 정확히 돌아오기 쉬워야 한다.
  - 멈춘 구간을 지나면 100%에서 이어서 바뀐다(튀지 않는다). 손가락 간격 비의 로그에서 멈춤 폭만큼을 뺀다.
  - 양 끝을 넘어 더 오므리거나 벌려도 쌓아 두지 않는다. 방향을 바꾸면 바로 반응한다.
  - 100%에 들어서는 순간 짧게 진동한다(`navigator.vibrate`, Android만).
- 손가락 사이의 그리드 지점이 손가락 아래에 머물도록 상자의 가로 스크롤과 페이지 세로 스크롤을 함께 맞춘다.
- **손가락이 움직이는 동안은 `transform: scale()`만 바꾸고, 손을 뗄 때 한 번 `zoom`으로 확정한다(`finishPinch`).**
  `zoom`은 그리드 전체를 다시 배치하고 칠해서 프레임마다 쓰면 휴대폰에서 끊긴다. 느린 것은 JS가 아니라 브라우저의 배치라서,
  시그널이나 요소별 크기 지정으로 바꿔도 같다.
  - 상자(`.grid-wrapper`) 높이를 같은 배율로 맞춘다. 아래 Agreement 패널이 핀치 동안 따라 움직이고 손을 뗄 때 튀지 않는다.
  - `will-change: transform`을 둔다. 확대하는 동안 글자가 흐리다가 손을 떼면 선명해지는 것이 정상이다. 빼면 배율마다 글자를 다시 그린다.
  - 줄인 그리드는 원래 폭만큼 스크롤되므로 가로 스크롤을 줄인 폭 기준으로 직접 제한하고, 핀치 동안 상자의 세로 넘침을 숨긴다(`.pinching`).
  - sticky 시간 축은 scale 전에 위치가 정해져서 상자 왼쪽 끝에서 벗어난다. 그 차이를 시간 축 요소마다 `--pinch-shift`(`translate`)로 되돌린다.
    그리드에 한 번 걸면 변수가 상속되어 전체 스타일 계산이 다시 돈다.
- **줌은 100% 배치를 그대로 키우고 줄인다(`--grid-width`).** 100%가 아닐 때 그리드 폭을 100%일 때의 폭으로 고정한다.
  고정하지 않으면 넓은 화면에서 확대할 때 열 폭이 바뀌고 글이 다시 줄바꿈되어 손을 뗀 뒤 셀이 튄다.
  화면 폭이 바뀌면(회전) 배율은 두고 새 폭으로 다시 고정한다.
- 배율은 요일 탭 상태와 함께 `sessionStorage`에 둔다(자동 새로고침 뒤에도 유지).
- 그리드 밖(헤더 등)의 핀치와 `zoom` 미지원 브라우저는 브라우저의 페이지 줌 그대로다(`@supports`).
